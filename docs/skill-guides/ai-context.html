01 — 라우팅

언제 쓰고 언제 안 쓰는가

형제 스킬과의 경계가 SKILL.md Constraints 에 명시돼 있다. 이 스킬은 문서 내용만 다루며, 파일 배치나 셸 품질은 대상이 아니다.

AGENTS.md 가 업계 기준에 맞는지 점검

check

새 프로젝트에 컨텍스트 문서를 처음 만든다

create

비대해진 CLAUDE.md 를 중첩 파일로 쪼갠다

refactor

SKILL.md 를 점검한다

→ skill:check

*.sh 를 점검한다

→ sh:check

저장소 디렉터리 구조를 점검한다

→ packaging:structure-check

02 — 인터페이스

호출 형식

/harness:ai-context [action] [path] [--file PATH] [--type TYPE] [-h]
인자와 플래그 목록
인자 / 플래그설명기본값
actioncheck / create / refactor / helpcheck

-h, --helpreferences/help.md 를 그대로 출력하고 중단—

03 — 파이프라인

동작 단계

네 단계는 순차 실행된다. Step 3 의 세 갈래를 펼쳐 각 액션의 계약을 확인한다.

1

인자 파싱

알 수 없는 action 이면 help 를 출력하고 중단한다.

2

대상 파일 결정

--file 이 없으면 cwd 에서 CLAUDE.md → AGENTS.md → GEMINI.md 우선순위로 자동 탐지한다. 여러 개가 발견되면 최우선 파일을 감사하고 나머지는 WARN 으로 보고한다. 자동 덮어쓰기는 절대 하지 않는다.

3

액션 디스패치

세 갈래 중 하나로 분기한다.

check 감사 리포트 읽기 전용
references/checks.md 의 core 체크(C1–C7) + 어댑터 체크를 실행한다. 판정 근거가 된 줄을 인용한다. 파일을 변경하지 않는다.
create 새 컨텍스트 문서 확인 후 쓰기
프로젝트 규모를 분류해 references/templates/ 에서 맞는 템플릿을 고르고, 계획을 제시한 뒤 확인을 받고 쓴다.
refactor 중첩 문서 구조 확인 후 쓰기
중첩 파일로 옮길 섹션 목록을 분할 계획으로 제시하고, 확인을 받고 추출한다.
4

리포트

references/report-template.md 형식. FAIL 이 하나도 없으면 [OK], 있으면 [FAIL]. 항상 Next: 줄로 끝난다.

05 — 안전 계약

주의사항 / 제약

check 는 감사 전용이다 — 어떤 경우에도 파일을 변경하지 않는다.

create / refactor 는 덮어쓰기 전에 반드시 확인을 받는다.

컨텍스트 파일이 여러 개 존재할 때 자동 덮어쓰기는 허용되지 않는다.

N/A 판정은 pass / fail 집계에 포함되지 않는다.

Step 1–3 이 실패하면 (help 출력이나 skill:check / sh:check 라우팅 중단은 제외) [FAIL] 리포트를 내고 멈춘다.
