01

언제 쓰고 언제 안 쓰는가

쓰임이 겹쳐 보이는 이웃 스킬이 셋 있다. 판단 기준은 하나 — 대상이 무엇인가.

✅ 내장 스킬이 내부에서 무엇을 하는지 뜯어보고 기록하고 싶다 사용
✅ 내장 스킬의 원문 프롬프트를 보존하고 싶다 사용
⛔ 설치한 플러그인을 문서화하고 싶다 harness:plugin-guide
⛔ 내가 만든 SKILL.md 를 점검하고 싶다 skill:check
⛔ 스킬을 새로 만들고 싶다 skill:create

plugin-guide

설치된 플러그인의 캐시된 SKILL.md 를 읽는다 — 디스크에 있는 정적 파일.

dissect-builtin

내장 스킬의 런타임 프롬프트 를 대상으로 한다 — 로드 시점에 주입되는 원문.

02

호출 형식

인자는 하나. 해부할 내장 스킬의 이름이다.

/harness:dissect-builtin <skill-name>
/harness:dissect-builtin -h
인자설명필수
<skill-name> 해부할 내장 스킬 이름 (예: keybindings-help) 예
-h, --help references/help.md 를 그대로 출력하고 중단 —
03

동작 단계

로드 한 번 → 에이전트 둘로 갈라짐 → 다시 하나로 합쳐 보고. 핵심은 가운데의 병렬 팬아웃이다.

1

스킬 프롬프트 로드

Skill(skill: "<skill-name>") 로 대상 내장 스킬을 로드한다. 주입된 원문 전체를 그대로 보존한다.

2 · 에이전트 2개를 한 메시지에서 동시 실행
Agent 1 claude/built-in-skills/<name>/README.md

한국어 분석 문서. 한줄 요약 → 동작 단계(Phase) → 상세 체크 항목 → 특징 순. 제목은 대상 스킬의 실제 흐름에 맞게 조정하고, 고정 템플릿을 억지로 맞추지 않는다.

Agent 2 claude/built-in-skills/<name>/PROMPT.md

원문 그대로. 로드된 프롬프트를 손대지 않고 옮긴다 — 요약도, 번역도, 재포맷도 없다.

3

완료 확인

두 에이전트가 끝나면 스킬명, 산출 경로 2개, 다음 단계를 함께 출력한다.

04

주의사항 / 제약

다섯 개 중 앞의 셋은 산출물 자체의 계약이고, 뒤의 둘은 실패 처리 규칙이다.

PROMPT.md 는 원문의 정확한 복사본이어야 한다

요약 · 번역 · 재포맷 금지. 보존이 목적이므로 한 글자라도 다르면 산출물의 의미가 사라진다.

README.md 는 한국어로 쓴다

영어는 기술 용어에만 쓴다.

산출 파일 이름으로 SKILL.md 를 쓰지 않는다

Claude Code 의 스킬 로딩 메커니즘과 충돌한다.
