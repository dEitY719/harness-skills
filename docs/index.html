harness skills

코드가 아니라 AI 코딩 하네스 자체를 다루는 스킬 5개 — 컨텍스트 문서를 점검하고 쓰고, 하네스 전체를 감사해 그 결과를 적용하고, 내장 스킬과 설치된 플러그인을 한국어로 문서화합니다. 여섯 개 하네스에 설치되는 단일 플러그인 harness 로 묶여 있습니다.

5개 중 4개는 이 저장소 밖을 바꿉니다 — 사용자 하네스의 .claude/reports/, dotfiles 의 claude/built-in-skills/ 와 플러그인 인덱스가 그 대상입니다. 그래서 그 4개의 사용 예시 문서는 미실행 예시이며, 명령과 게이트는 각 SKILL.md 인용입니다. 읽기 전용인 ai-context check 하나만 실제 실행 기록입니다.

1스킬 5개

ai-context

/harness:ai-context [check|create|refactor] [path]

CLAUDE.md · AGENTS.md · GEMINI.md 한 벌을 감사하거나(check), 프로젝트 규모에 맞는 템플릿으로 새로 쓰거나(create), 비대해진 파일을 중첩 파일로 쪼갠다(refactor). check 는 파일을 수정하지 않고, create 와 refactor 는 계획을 보여준 뒤 확인을 받고서야 쓴다.

설명서 사용 예시

harness-legacy-check

/harness:harness-legacy-check

컨텍스트 문서 · 스킬 · 워크플로우 · settings · hooks · MCP 를 훑어 .claude/reports/harness-legacy-check.md 에 리포트 1건을 남긴다. 읽기 전용 — 어떤 파일도 고치거나 지우지 않는다.

설명서 사용 예시

harness-refactor

/harness:harness-refactor

그 리포트를 읽어 항목을 위험도로 분류하고, low-risk 만 골라 claude/workflows/harness-refactor.js 를 새로 생성한 뒤 실행한다. 위험한 항목은 적용하지 않고 Final Report 의 "Human Approval Required" 섹션에만 기록된다.

설명서 사용 예시

dissect-builtin

/harness:dissect-builtin <skill-name>

Claude Code 내장 스킬 하나를 불러와 claude/built-in-skills/<name>/ 아래에 한국어 해설 README.md 와 원문 PROMPT.md 를 쓴다. PROMPT.md 는 요약도 번역도 재구성도 하지 않은 정확한 사본이다.

설명서 사용 예시

plugin-guide

/harness:plugin-guide <plugin>[@<marketplace>] [--force]

이미 설치된 플러그인의 캐시된 SKILL.md 들을 읽어 한국어 가이드 docs/guide/plugins/<plugin>.md 를 쓰고 인덱스에 한 줄을 끼워 넣는다. 플러그인을 설치하지 않고 커밋도 하지 않으며, 문서가 이미 있으면 --force 없이는 건드리지 않는다.

설명서 사용 예시

2다섯 개가 맞물리는 방식

다섯 개가 한 줄로 이어지는 파이프라인은 아니다. 짝을 이루는 것은 둘뿐이고, 나머지는 대상이 서로 다른 독립 스킬이다.

harness-legacy-check─▶ .claude/reports/harness-legacy-check.md─▶ harness-refactor

감사와 적용 — legacy-check / refactor

둘을 잇는 인터페이스는 세션이 아니라 리포트 파일 하나다. 앞은 기록만 하고 판단하지 않으며, 뒤는 그 기록을 읽되 low-risk 로 분류된 것 외에는 손대지 않는다. 리포트가 없으면 refactor 는 먼저 check 를 돌리라고 말하고 멈춘다.

두 갈래의 문서화 — dissect-builtin / plugin-guide

둘 다 한국어 문서를 쓰지만 대상이 다르다. 앞은 Claude Code 내장 스킬을 프롬프트 원문까지 남기고, 뒤는 설치된 플러그인의 SKILL.md 들을 요약해 가이드로 만든다. 어느 쪽도 커밋하지 않는다 — 검토와 커밋은 사람의 몫이다.

ai-context 의 경계

세 개의 컨텍스트 문서만 다루는 디스패처다. SKILL.md 가 들어오면 skill:check 로, *.sh 가 들어오면 sh:check 로 보내고 스스로는 처리하지 않는다. 컨텍스트 파일이 여러 개 발견되면 자동으로 덮어쓰지 않고 후보를 제시한다.

하네스에 따라 달라지는 것

다섯 개 모두 Claude Code 어휘로 쓰여 있다. Workflow 런타임이 없는 하네스에서 legacy-check 와 refactor 는 단계를 사람이 직접 밟는 manual 이 되고, 내장 스킬 카탈로그를 읽는 dissect-builtin 은 아예 동작하지 않는다. 하네스별 대체 방법은 이 저장소의 references/<harness>-tools.md 에 있다.
